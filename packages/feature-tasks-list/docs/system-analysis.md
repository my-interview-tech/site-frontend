# Системная аналитика

Пакет `@my-interview/feature-tasks-list` показывает разводящую задач технологии.
Поля документа описаны в [контракте](contract.md). Здесь поведение экрана.

## Границы

Пакет загружает список по `slug`, фильтрует его на клиенте и ведёт на экран задачи ссылкой из карточки.
Сам экран задачи — `@my-interview/feature-task`.

## Состояния экрана

`TasksView` выбирает экран по `getPageStatus`.

| Статус    | Условие                                         | Экран                                                             |
| --------- | ----------------------------------------------- | ----------------------------------------------------------------- |
| `loading` | идёт запрос                                     | `Skeleton`                                                        |
| `error`   | запрос упал или в корне нет обязательных ключей | `ErrorState`: «назад» вызывает `onBack`, повтор вызывает `reload` |
| `success` | загрузка прошла и ключи корня на месте          | `TasksContent`                                                    |

Обязательные ключи корня: `filters`, `items`, `slug`, `title`.

## Фильтрация

- Выбор задаёт хост через `selection` и `onSelectionChange`; без них виджет `tasks-content` держит его в `useState`. Список считает `filterTasks(items, selection)`.
- Сайт пишет выбор в query-строку с `replace`: выбор переживает переход в задачу и назад, ссылкой им можно поделиться. Последний выбор технологии хранится в `sessionStorage`, «Все задачи» на экране задачи ведёт на него.
- Решённые в этом браузере задачи (`useSolvedTasks` из `@my-interview/common`) получают `isStudied: true` до фильтрации.
- Внутри группы подходит любое выбранное значение, между группами — все группы сразу.
- Язык, сложность и темы — множественный выбор, статус — один из «Все / Не решённые / Решённые».
- Темы свёрнуты до восьми, выбранная тема видна и в свёрнутом списке.
- «Сбросить» активна, пока хоть одна группа сужает список.
- Счётчик в шапке считает отфильтрованные задачи.
- Пустой результат — подсказка «Ничего не нашли» и сброс, не `ErrorState`.
